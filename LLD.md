# Debaitify — Low-Level Design

**Status:** v3 (current) · **Date:** 2026-09-07 · Companion to [HLD.md](./HLD.md)

Written to be implementable and extendable without further design work. §14 is
the part to read when adding something.

---

## 1. Stack

| Concern | Choice |
|---|---|
| Language | TypeScript 7, `strict`, `noUncheckedIndexedAccess` |
| Bundler | Vite 8 + `@crxjs/vite-plugin` 2 |
| Validation | `zod` 4 — site config, model output |
| Extraction | `@mozilla/readability` (fallback path only) |
| Provider SDK | `@anthropic-ai/sdk` — imported **only** under `src/providers/` |
| Test | `vitest` + `jsdom`, 55 tests over 6 files |

No remote code, no `eval`, no CDN. MV3 forbids them.

│   └── status.ts            PageStatus type for the popup
├── sites/                   ← seam 2: sites

**`select.ts` is separate from `resolve.ts` on purpose.** The selector helpers
are pure DOM and are used by tests; `resolve.ts` touches `chrome.storage`. Merged,
importing a selector would have dragged the extension API into a test process.

## 3. Manifest

Generated by `manifest.config.ts` from `sites.json` — one `host_permissions`
entry and one `content_scripts.matches` glob per enabled site, so permissions
cannot drift from configured hosts.

Two content scripts:

| Script | World | `run_at` | Why |
|---|---|---|---|
| `content-script.ts` | ISOLATED | `document_start` | Needs to be in place before the headline paints |
| `bridge-main.ts` | **MAIN** | `document_idle` | `window.App` is invisible from the isolated world |

Permissions: `storage` plus `https://api.anthropic.com/*` and the site hosts.
No `tabs`, no `activeTab`, no `<all_urls>`.

> **Entry points must not share a basename.** Both were `index.ts`; the bundler
> emitted colliding chunk names and `service-worker-loader.js` imported the
> *content script* chunk. The extension loaded without error and did nothing.

## 4. Storage

Three namespaces in `chrome.storage.local`.

### 4.1 `settings`

```ts
export type Strategy = "lead" | "model-lead" | "model-article";

export interface Settings {
  provider: string;                      // provider id, e.g. "claude"
  model: string;
  apiKeys: Record<string, string>;       // per provider — switching keeps both
  strategy: Strategy;
  siteEnabled: Record<string, boolean>;  // by site id; absent means enabled
  revealTimeoutMs: number;               // 1500
  cacheTtlDays: number;                  // 30
  negativeCacheTtlHours: number;         // 24
  debug: boolean;
}
```

`loadSettings()` spreads over `DEFAULT_SETTINGS`, so a field added in a later
version is populated for existing users without a migration.

### 4.2 `siteOverrides`

A partial `SitesFile`, deep-merged over the bundled config and re-validated.

### 4.3 Cache — one key per article

Key: `c:<siteId>:<articleId>`. One storage key per entry rather than a single
map, so a write touches ~200 bytes instead of rewriting everything.
`chrome.storage.local` has no write-rate limit (unlike `storage.sync`).

```ts
type CacheStatus = "ok" | "refusal" | "invalid-output";
type CacheOrigin = "lead" | "body";

interface CacheEntry {
  status: CacheStatus;
  origin: CacheOrigin;      // provenance — see §4.4
  headline: string | null;  // null unless status === "ok"
  original: string;
  provider: string;         // invalidation triple
  model: string;
  promptVersion: number;
  createdAt: number;
  lastUsedAt: number;
}
```

A read is a hit only if the entry exists, `provider`/`model`/`promptVersion` all
match, `origin` is in the caller's `accept` list, and it is inside TTL — 30 days
for `ok`, 24 hours for the two negative statuses.

**An `ok` entry with a null headline is corrupt**: it is dropped and regenerated
rather than reported as a failure the caller cannot act on.

Eviction: `cacheCount` tracked; over 500 triggers a TTL sweep then LRU down to
the cap. ~100 KB against a 10 MB quota, so the sweep is rare.

### 4.4 Provenance

A front-page rewrite is grounded only in the lead; an article rewrite reads the
whole body. Both cache under the same article id, so:

| Caller | `accept` |
|---|---|
| Article page | `["body"]` — refuses lead-grade, regenerates |
| Front page | `["lead", "body"]` — a body-derived headline is strictly better |

An entry with no `origin` predates the field and is treated as `lead`.

## 5. Message contract

`shared/messages.ts` is the single source of truth; both sides import it.

```ts
export type Message =
  | { type: "lookup"; key: string }                 // cache probe, no DOM needed
  | { type: "rewrite"; payload: RewriteRequest }    // one article, body-grounded
  | { type: "rewriteBatch"; payload: BatchRequest } // N teasers, lead-grounded
  | { type: "stats" }
  | { type: "purgeCache" };

export type FailureReason =
  | "no-api-key"     // not cached
  | "disabled"       // not cached
  | "refusal"        // CACHED 24 h
  | "invalid-output" // CACHED 24 h
  | "rate-limited"   // not cached
  | "api-error"      // not cached
  | "timeout";       // not cached

export const CACHEABLE_FAILURES: ReadonlySet<FailureReason> =
  new Set(["refusal", "invalid-output"]);
```

The URL is **not** in any request. The content script resolves the article key
itself; the worker never learns which page the user is on beyond the site id.

Every `FailureReason` produces one content-script behaviour — leave the original
alone. The distinction drives only the popup and whether a negative cache entry
is written.

## 6. Site configuration

```ts
const SiteConfigSchema = z.object({
  id: z.string(),            // stable — appears in cache keys
  label: z.string(),
  enabled: z.boolean(),
  hosts: z.array(z.string()).min(1),          // exact hostnames, not globs
  article: z.object({
    urlPattern: z.string(),                   // RegExp on pathname, named group `id`
  }),
  headline: z.object({ selectors: Selectors.min(1) }),
  lead:     z.object({ selectors: Selectors }),
  body: z.object({
    containers: Selectors.min(1),
    paragraphs: Selectors.min(1),
    strip:      Selectors,
  }),
  front: z.object({
    teaserLinkSelectors: Selectors.min(1),    // identity anchors
    titleSelectors:      Selectors.min(1),    // where the text lives inside them
    stateSource: z.enum(["iltalehti", "next-data", "none"]),
    minTitleChars: z.number().int().positive(),
  }),
  paywall: z.object({
    useJsonLd: z.boolean(),
    selectors: Selectors,
    minFreeChars: z.number().int().positive(),
  }),
  minBodyChars: z.number().int().positive(),
  maxBodyChars: z.number().int().positive(),
});
```

**Every selector field is an ordered candidate list.** `selectFirst` returns the
first that matches and *skips* invalid CSS rather than throwing —
`querySelector` raises `SyntaxError`, and one typo in a user override must not
kill the content script.

Shipped values (validated against captured HTML):

| | Iltalehti | Ilta-Sanomat |
|---|---|---|
| Article URL | `/<cat>/a/<uuid>` | `/<cat>/art-<digits>.html` |
| Headline | `h1.article-headline` | `h1[class*='article-title']` |
| Body | `.article-body` → `p.paragraph` | `.article-body` → `p` |
| Teaser anchor | `a[href*='/a/']` | `a[href*='/art-']` |
| Teaser title | `.front-title` | `[class*='teaser-title']` |
| State source | `window.App` | `__NEXT_DATA__` |
| Paywall | length gate only (no JSON-LD) | JSON-LD `isAccessibleForFree` |

Overrides are deep-merged by site `id` and re-validated. **On validation failure
the override is discarded entirely** and the bundled config used, with the error
surfaced in Options.

## 7. Content script

### 7.1 Mode selection

```ts
const isArticle = articleKey(location.pathname, site) !== null;
```

That is the whole article test — a path yielding no id is not an article, so
there is no separate `isArticle()` heuristic to keep in sync.

### 7.2 Front pipeline (`front.ts`)

```
collect(site)                     anchors → { id, title, elements[] }
  ↓ skip ids already in `done`
strategy === "model-article"?     → runFromArticles(), return
window.postMessage({__debaitifyAsk})   ask bridge to re-read
waitForLeads()                    ≤1200 ms
  ↓
strategy === "lead"?              → swap title := lead, no API call, return
  ↓
sendMessage("rewriteBatch")       → { id → headline }
swap each element in place
```

`collect()` walks teaser anchors, parses the id from `href` via the site's
`urlPattern`, and finds the title element inside the anchor. Teasers are keyed by
id, so one story appearing twice yields one entry with two elements — and both
get swapped.

Ids are added to `done` **before** the await, so a MutationObserver tick during
the request cannot queue them again. On a transient failure they are removed
again so the next tick retries.

### 7.3 Article pipeline

`extract()` → `sendMessage("rewrite")` → `swap()`, wrapped in the anti-flash
state machine (§9).

### 7.4 Navigation

Both sites are SPAs. `navigation.ts` fires on `DOMContentLoaded`, patched
`pushState`/`replaceState`, `popstate`, and a `MutationObserver` on
`documentElement` debounced at 250 ms.

Three guards, all load-bearing:

- Track `processedKey` (the article key, not the URL) and ignore unchanged triggers.
- **Disconnect the observer before writing, reconnect after** — otherwise the
  swap re-triggers the observer, which re-triggers the swap, forever.
- Carry a monotonic `runId`; drop stale results so a late response is never
  applied to a different article.

## 8. MAIN-world bridge

`bridge-main.ts` runs in the page's own global scope, reads teaser state, and
posts `{ __debaitify: "teasers", leads: Record<id,string>, source }` via
`window.postMessage`. It re-reads on `{ __debaitifyAsk: true }`.

| Site | Source | Coverage |
|---|---|---|
| Iltalehti | `window.App.state.fronts` → `.content.{article_id,lead}` | 100% of teasers in state |
| Ilta-Sanomat | `#__NEXT_DATA__` → `{href, ingress\|lead\|description}` | SSR'd teasers only, ~40% carry a lead |

Both readers are a bounded recursive walk (depth ≤ 12) wrapped in try/catch: a
shape change inside the page's own world must degrade to zero leads, never throw.

> `window.App` is a **JS object literal containing bare `undefined`** — not valid
> JSON. That is why the bridge must read the live object rather than parsing the
> HTML, and why a service-worker-side fetch of the front page cannot substitute.

## 9. DOM writes

### 9.1 Mixed content

Teaser titles are `<span class="front-text-sticker">Näkökulma</span>` followed by
the headline as a bare text node. Two consequences:

- `headlineTextOf()` uses `ownText()` — direct child text nodes only — so the
  sticker is not sent to the model as part of the headline.
- `writeHeadline()` rewrites **text nodes only** when element children are
  present. Setting `textContent` would delete the sticker.

`textContent` is always used over `innerHTML`: model output must never be parsed
as HTML.

### 9.2 Anti-flash (article pages only)

Arming happens at `document_start`, before the `<h1>` exists, so a stylesheet
keyed on the site's headline selectors is injected instead:

```css
html[data-debaitify-armed] h1.article-headline:not([data-debaitify]) {
  opacity: 0 !important;
  animation: debaitify-failsafe-reveal 0s linear 2500ms forwards;
}
```

`opacity`, never `display:none` — the box is preserved, so no layout shift. The
animation is the failsafe: if the script throws, CSS reveals the headline at
2.5 s regardless. Combined with the JS `revealTimeoutMs`, **there is no path that
leaves a headline permanently hidden.**

Selectors are interpolated into a stylesheet, so `isSafeSelector()` rejects
anything containing `{}<>@;` or that the engine cannot parse.

## 10. Provider layer

```ts
interface GenerateRequest<T> {
  system: string; user: string; maxTokens: number;
  schema: z.ZodType<T>; schemaName: string;
}
type GenerateResult<T> =
  | { ok: true; value: T; usage?: TokenUsage }
  | { ok: false; reason: FailureReason; detail?: string };

interface ModelClient { generate<T>(r: GenerateRequest<T>): Promise<GenerateResult<T>>; }

interface ProviderEntry {
  meta: ProviderMeta;
  create(o: { apiKey: string; model: string }): ModelClient;
  testKey(apiKey: string): Promise<{ ok: boolean; detail: string }>;
}
```

`testKey` lives on the provider so the Options page never knows a vendor's
endpoint or headers.

`createClient()` falls back to the default provider when a stored id is unknown,
and to the provider's default model when a stored model is not offered — so a
removed model cannot brick the extension.

### Claude specifics

| | |
|---|---|
| Browser use | `dangerouslyAllowBrowser: true`. The SDK then adds `anthropic-dangerous-direct-browser-access: true` itself — gated on the *option*, not on runtime detection, so it works from a service worker |
| Opus 5 | `thinking: {type:"adaptive"}` + `effort: "low"`. Disabling thinking outright can leak internal tags into the visible response |
| Haiku 4.5 | Neither parameter — it rejects `effort` and has no adaptive thinking. Encoded as an empty `MODEL_TUNING` entry, not an `if` |
| Errors | `AuthenticationError` → `RateLimitError` → `APIConnectionTimeoutError` → `APIConnectionError` → `APIError`. Connection *before* `APIError`: in this SDK it is a subclass |

## 11. Headline generation

`background/headlines.ts` — vendor-neutral.

| | Single | Batch |
|---|---|---|
| Prompt | `SYSTEM_PROMPT` | `BATCH_SYSTEM_PROMPT` |
| Input | article body | `id / headline / lead` blocks |
| Schema | `{ headline: string }` | `{ headlines: [{ id, headline: string \| null }] }` |
| `maxTokens` | 512 | 8192 |

`maxTokens` is generous because the cap counts thinking tokens; the schema, not
the cap, is what keeps headlines short.

**The batch prompt permits `null`**, and lists when to use it: boilerplate lead,
insufficient facts, an advertisement, or a headline that is already plain. The
prompt says so explicitly — *"Returning null is correct and expected. A wrong
headline is worse than a clickbait one."*

The original title is **not** sent on the single-article path: supplying it
biases the rewrite toward the framing being removed.

`isAcceptable()` is a cheap guard, not a quality judge: 15–120 chars, ≤14 words,
no `?` or `…`, no leading quote (**including `”` — Finnish opens quotes with the
same glyph it closes with**), no 5+ consecutive capitals, not identical to the
original.

`PROMPT_VERSION` is bumped when a prompt changes; cached entries carrying an old
version are misses.

## 12. Concurrency

| Limiter | Value | Where |
|---|---|---|
| Worker in-flight dedupe | by cache key | `queue.ts` — a refresh mid-generation joins the existing promise |
| Worker concurrency | 2 | `queue.ts` |
| Batch chunk | 40 teasers | `service-worker.ts` |
| Article fetches | 3, gated on `IntersectionObserver` | `front.ts` |

The `model-article` strategy fetches in the **content script**, not the worker:
a service worker has no DOM and therefore no `DOMParser`, and parsing in the
content script lets it reuse the same config-driven extractor. Fetches are lazy
because doing all 60 up front would be ~24 MB for a page you may not read.

## 13. Testing

| File | Covers |
|---|---|
| `text.test.ts` | soft hyphens, `fold`, `stripLeadingTitle`, `similarity` |
| `sites.test.ts` | schema validity, every selector parses, id extraction incl. query strings |
| `extract.test.ts` | golden numbers per site, paywall via JSON-LD, live DOM untouched, heuristic fallback |
| `front.test.ts` | teaser collection, sticker preservation, swap/revert, state carries leads |
| `output-guard.test.ts` | `isAcceptable` incl. the Finnish `”` case |
| `providers.test.ts` | registry, fallbacks, default-settings drift |

**Golden numbers are the redesign alarm.** Paragraph counts are exact (11 for IL,
14 for IS); character counts are banded pending a live run. When one fails,
re-capture the fixture, confirm the markup, and update deliberately.

No test calls a live API.

## 14. Extension recipes

### Add a site

1. Add an entry to `src/sites/sites.json` — hosts, `article.urlPattern` with a
   named `id` group, and candidate selectors for `headline`, `lead`, `body`,
   `front`.
2. Set `front.stateSource` to an existing reader, or `"none"` (then only the
   `model-article` strategy will work there).
3. Capture a front page and an article into `tests/fixtures/`, add golden-number
   assertions.
4. `npm run build` — the manifest picks up the hosts automatically.

Selectors only? Users can do steps 1 and 4 themselves via Options → Site
configuration, with no rebuild.

### Add a provider

1. Implement `ModelClient.generate()` in `src/providers/<name>.ts`: map
   `GenerateRequest` to the vendor's structured-output mechanism, map errors to
   `FailureReason`, return `usage` if available.
2. Export a `ProviderEntry` with `meta` (models + per-1M pricing), `create` and
   `testKey`.
3. Replace the `declared({...})` stub in `registry.ts` with it.

Nothing else changes. Prompts, schemas, batching, caching and the Options UI are
all driven off `meta`.

### Add a strategy

1. Extend the `Strategy` union in `shared/settings.ts`.
2. Add a branch in `runFront()`.
3. Add an entry to `STRATEGIES` in `options/main.ts` — label, honest cost
   estimate, whether it needs a key.

### Add a browser

1. Wrap any new extension API in `shared/platform.ts`.
2. Adjust the background declaration in `manifest.config.ts`.

### Add a page mode

Mode selection is one line in `content-script.ts`. A new mode is a new predicate
plus a pipeline module alongside `front.ts`.

## 15. Build

```bash
npm install
npm run typecheck
npm run test
npm run build      # → dist/, load unpacked
```

After a rebuild, click ↻ on the extension card **and** reload the page. Settings
are read once at page load.

**`UNABLE_TO_GET_ISSUER_CERT_LOCALLY` on `npm install`:** Node bundles its own CA
store and lacks `GlobalSign Root CA` (R1), which anchors the cross-signed chain
npm's registry presents. Supply it from the system keychain via
`NODE_EXTRA_CA_CERTS` — see README. Do not disable `strict-ssl`.

## 16. Known gaps

| Gap | Detail |
|---|---|
| **Never run live** | Front-page code was written against pre-hydration HTML with 6 teasers; the real page renders dozens. No live API call has been made from the extension |
| IS coverage | `__NEXT_DATA__` holds only SSR'd teasers, ~40% with a lead |
| IL paywall | No JSON-LD; only the length gate defends against Plus stubs |
| No icons | Manifest ships none; Chrome shows a puzzle piece |
| Char-count goldens | Banded, not pinned — tighten after the first real run |
